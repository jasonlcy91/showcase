Philosophy · How I work

Three tenets that
shaped every decision.

Tenet 01
Agile, collaborative delivery
Short feedback loops beat long plans. I involved stakeholders at many stages — from reviewing context design to UAT. Decisions get made together, not in silo.
Tenet 02
Context is the product
For LLM systems, the quality of the output is entirely determined by the quality of what goes in. I treat context engineering with the same rigour as code: clean it, verify it, benchmark it, and never assume the model can compensate for bad input.
Tenet 03
Prove at small scale, then commit
Don't scale until proven. I introduced a framework to manage expectation: Quick POC -> Break down milestones -> UAT -> Evidence -> Scale -> Repeat. Evidences — Scores, cost projections, per-case diffs — is what earns the right to scale up.

Engineering · Details & craft

The craftmanship behind that make
production actually work.

Engineering in the details — invisible until they break at scale.

01 / 05
HTML → Markdown transcript cleaning
D365 activity descriptions arrive as raw HTML soup — nested tables, inline styles, image tags. I built a two-pass cleaner: first markdownify converts structure to readable Markdown, then a custom pass trims email history past the first blockquote (the repeated chain that bloats every email thread). Result: ~40% token reduction per transcript at no information loss.

03 / 05
Private D365 images — full caching pipeline
KB articles embed screenshots and SOP diagrams behind Microsoft auth — inaccessible to the LLM directly until we send as base64 URI. I built an authenticated download layer inside t1 (KB sync) with a persistent local cache: first run fetches and stores, subsequent runs hit cache, while gracefully taking care of rate-limit. 12,400+ images cached to date.
t1image handling
04 / 05
Optimize transformation with performance on Databricks + DAB deployment
The transcript aggregation step (t2) processes millions of rows per run with unavoidable PandasUDF. I benchmarked four approaches — Spark windows, applyInPandas, mapInArrow, and a hybrid — settling on applyInPandas for the best performance. The full pipeline is deployed via Databricks Asset Bundles (DAB), giving us version-controlled, parameterised job definitions that can be deployed across environments.
t2PySparkDABperformance
05 / 05
Prompt caching by context arrangement
OpenAI's prompt can cache stable, repeated content at the start of the prompt. I deliberately structure every request so the system prompt + criteria block (identical across all evaluations) comes first — making it a permanent cache hit — while the per-case transcript appears only at the end. This arrangement alone saves ~30% of token costs at scale.
